# Changelog

## Unreleased

- **PHP and Laravel apps get a real map:** a Laravel app showed no endpoints, and its PHP files no connections, because Floorplan only followed `require`. Reported by @epistex-dev in #67, fixed by @Basel-Alsemsam in #106. Now:
  - **PHP files link to the classes they use**: `use` statements (grouped and aliased ones too), traits, and classes named without one (`new Order`, `Order::class`, parameter types, `extends`), found by namespace and through `composer.json`'s PSR-4 folders. Outside packages are named by vendor (`composer:Illuminate`). PHP is read, never run.
  - **Laravel endpoints with their full address**: `Route::get/post/…`, `match`, `resource` and `apiResource` (with `only`/`except`), `Route::view` and `Route::inertia`, under prefix, name, middleware and controller groups. A route file loaded inside a group (`require`, `->group(base_path(…))`, files required in a loop over a fixed list, `withRouting` in `bootstrap/app.php`) gets the group's prefix, name and middleware.
  - **Each endpoint sits in the controller method that answers it**, with that method's doc comment, so requests lead to the code that handles them rather than to the routes file.
  - **Laravel Wayfinder calls** (`import { show } from '@/routes/orders'`, `OrderController.update.form(…)`) reach their endpoints by route name or controller method, though Wayfinder's generated files aren't in git. A name defined twice is left unlinked rather than guessed.
  - **Inertia pages are screens**: a controller method that renders a page makes it a screen at the endpoint's address, with the controller and its data behind it.
  - **Health checks who may call each Laravel endpoint**: middleware on the route, its groups and the route files around it (through the app's own aliases and groups), the controller's own middleware, a form request whose `authorize()` looks at the user, and checks inside the method (`$this->authorize`, `Gate::`, `abort_unless(…, 403)`). Sign-in pages (`guest`), closures that only redirect or answer something fixed, and plain pages aren't reported. Each open endpoint's fix names the file it's registered in.
- **Privacy, terms and legal pages are public on purpose:** Health no longer reports reading a site's `/privacy`, `/privacy-policy`, `/terms`, `/terms-of-service`, `/tos`, `/legal` or imprint page as open to anyone. Only reading counts, and only when the whole address is the page (`/legal/imprint` too), so someone's privacy settings (`/account/privacy`), data under a legal address (`/api/legal/cases`), a request like `/api/privacy-requests` and a change to one of those pages are still checked. Fixed by @Basel-Alsemsam in #106.

## 0.9.0 (2026-11-14)

- **Flask login checks are recognised:** routes protected by `@login_required`, `@login_required_json` or `@logged_in_required` were reported as open, because names starting with "log" were taken for logging decorators. Logging decorators such as `@log_call` still do not count as login checks, and a login decorator placed above the route remains a warning. Reported by @SmmSrg in #123, fixed by @daniyyell-dev in #125.
- **FastAPI apps protected by one HTTP middleware:** an `@app.middleware("http")` function that turns callers away (a 401 or 403 response, or `HTTPException`) now counts as the app's login check, so its endpoints are no longer reported as open to anyone. It works the same way Flask's `@app.before_request` already does. A middleware that only adds headers, measures time or reads a 401 from the response still protects nothing, whatever its name, and neither protects a JavaScript server in the same repo. Reported by @ahmedjanwar in #86 and fixed by them in #87.
- **FastAPI checks named `validate_…`:** a dependency like `Depends(validate_jwt)` or `Depends(validate_api_key)` now counts as a login check. One that validates a request's shape, like `@validate` or `Depends(validate_payload)`, still doesn't. Reported by @doramirdor in #112.
- **FastAPI checks judged by what they do, not only their name:** a route was reported as open when its check was the result of a factory (`editor = require_role("editor")`, then `Depends(editor)`, on the route or on the whole `APIRouter`), a dependency with an ordinary name that turns callers away with a 401 or 403 (`Depends(current_vehicle)`, or a class whose `__call__` does), a `Depends()` kept in a variable (`api = Depends(require_key)`, then `dependencies=[api]` or `_: None = api`), or a list kept in a constant (`dependencies=WRITE`). These now count. A dependency that checks nothing about the caller, like a page number or a lookup that answers 404, still protects nothing however it's passed. Reported by @RoelfA in #117 and @SomeRandomChad in #102.
- **Imports stay linked when TypeScript settings come from several files:** local arrays in `tsconfig.json`'s `extends` now preserve inherited path aliases. Later configurations and the project's own settings take precedence, and relative paths keep the correct starting directory. Reported by @daniyyell-dev in #126, fixed by @daniyyell-dev in #127.
- **Imports through package.json "imports" are linked:** projects that import with Node subpath imports, like `import { money } from '#lib/money'` mapped by `"imports": { "#*": "./src/*" }`, had almost no links between their own files, so the map showed parts that seemed unconnected and Health listed most files as unused. Floorplan now follows the `imports` field of the nearest package.json the way Node does: an exact key first, then the most specific `*` key, trying each target and condition in turn (`types` last, since Node never picks it). tsconfig `paths` still apply when package.json has no match. Reported by @joelbeedle in #69, fixed by @joelbeedle in #68.
- **Python imports between Django apps are linked:** in a project with its apps in a package (`apps/orders/`, `apps/core/`), `from apps.orders.models import Order` was linked to the importing app's own `apps.py`, so the map had no links between apps and Health listed much-used files as unused. Floorplan now looks for the whole module in every folder an import can start from before settling for part of it. Reported by @m1fril in #99.
- **Kotlin and Java files are linked to what they use:** an import of a class, function, value or type alias that isn't named after its file (Kotlin files often hold several) was listed as an outside Maven package, often the app's own (`com.example.app`), and code a file uses from its own package, which needs no import, wasn't linked at all, so the map had few links between Kotlin files and descriptions said files were unused. Floorplan now knows every top-level declaration in a file, links a file to the files of its own package (and of a `.*` import) whose names it uses outside comments and strings, and never lists one of the project's own packages as an outside package. Private declarations, and test helpers used from outside the tests, aren't linked. Reported by @RoelfA in #115.
- **Fewer false "secret key" alarms in Health:** a variable handed along (`MYSQL_PWD="$DB_PASSWORD"` in a shell script, `"$password"` in PHP, `%DB_PASSWORD%` on Windows), a path to one of the project's own files under a password-ish key (`'confirm_password' => 'resources/js/pages/auth/confirm-password.tsx'`), and a ULID record id under a plain `…Token` name are no longer reported as secrets written into the code. Access, auth and secret tokens are still checked whatever their value looks like. Fixed by @Basel-Alsemsam in #104, which also fixes #116 (reported by @BechtelCanDoIt).
- **More values that only look like secrets are left alone:**
  - variables in more spellings: `$(dbPassword)` in Azure Pipelines and Makefiles, `#{password}` in Ruby, a few joined together (`"$DB_USER:$DB_PASSWORD"`), and psql variables in database set-up scripts (`-v app_password="$APP_PASSWORD"`, then `PASSWORD :'app_password'`). Prompted by reports from @jeanlima17-cmd in #110 and @auroraferraz in #107 and #108;
  - publishable keys, which services make to be put in web pages: `pk_…` (Stripe, Clerk and others), Supabase's `sb_publishable_…` and PostHog's `phc_…`. A `sk_…` key is still flagged, and so is a password that happens to start with `pk_`. Reported by @notrdd in #119;
  - the two answers of a choice, like `mode === 'signup' ? 'new-password' : 'current-password'`, and the browser's autofill words (`new-password`, `one-time-code`). Reported by @adlewis82 in #93;
  - made-up keys with a run of the alphabet or the digits in them (`ghp_abcdefghij…0123456789…`), even in a well-known format. A random-looking key is still flagged, in test files too. Reported by @lexerio-seth in #101.
- **Fewer files wrongly called unused:** Expo Router finds every file in an app's `app/` folder by its place, so in an app that uses `expo-router` those screens no longer look unused (a leftover file in a Next.js `app/` folder, or anywhere else, still does). And a file with dots in its name, like `users.service.ts`, now counts as used when another file names it (`'./users/users.service'`), as `users.ts` already did; before, the dot hid the name, so NestJS services and controllers reached through an import the map couldn't follow looked unused. Reported by @axelmorand-afk in #88 and #89, with the dotted-name cause found by @xunguangzlj-cloud in #100.
- **Asking a question on the map no longer fails with “Prompt is too long”:** two things could fill Claude Code’s context before it got to the question. On a computer with many MCP servers set up (connectors and plugins), each question loaded every one of their tool descriptions, though answers never use them; now questions run with no MCP servers at all, which also makes each one much cheaper. And Claude Code could open the map’s own generated `floorplan/index.html` (about 2 MB on one line); it’s now told not to read that file or the map’s other generated files. Codex has no switch that turns off only its MCP servers, so it still loads them. Reported by @Kadreev in #66, with the second fix by @psingh-valorx in #120.
- **JSON files saved on Windows work:** Windows PowerShell's `Set-Content` and `Out-File`, and some editors, start a file with an invisible byte order mark, and Floorplan stopped with `architecture.json is not valid JSON: Unexpected token`. Every file you or an agent write for Floorplan (`architecture.json`, `descriptions/`, `recent-work.json`, `plan.json`, saved flows and Health dismissals) now reads the same with one. The guides also say that their commands are written for a POSIX shell, with the PowerShell way where it differs. Reported by @fjjjuv in #95, with a first version of the fix by @1oridevs in #97.
- **The map says what it leaves out:** only code is mapped unless `architecture.json`'s `include` names other kinds, so on a big project the map could look too small, as if the scan had failed. The scan and the build now say what isn't on the map, for example `NOT MAPPED  140 asset · 52 docs · 38 config`, and how to add a kind, and `--json` gives the same counts (`notMapped`). Reported by @fjjjuv in #95.
- **Open in editor opens your editor:** **Open in editor**, **Open handler** and the right-click item always made a VS Code link. Now `"editor"` in `architecture.json`, or `--editor` on the map's server (also passed on by `open.mjs`, or `FLOORPLAN_EDITOR`), picks another: a name (`cursor`, `windsurf`, `zed`, `vscode-insiders`, `vscodium`, `idea`, `phpstorm`) or a link of your own like `zed://file/{path}:{line}`. Only editors' own link schemes are accepted, never a web, `file:`, `javascript:` or `data:` link, and the map checks again before it builds one. VS Code stays the default. File names with `#`, `&` or `?` in them now open correctly too. See [Choosing the editor](docs/using-the-map.md#choosing-the-editor). Asked for by @deniskern in #122.
- **Row-level security switched on in a loop is recognised:** a Supabase migration that switches it on for many tables at once (`foreach t in array array['wallets', …] loop execute format('alter table public.%I enable row level security', t); end loop;`) left every one of those tables reported as "Anyone can read and change". The names in the loop's list now count as switched on, also for a list declared first, `FOR … IN SELECT unnest(…)` and statements glued together with `||`. When a migration switches it on for tables it doesn't name (a loop over `pg_tables`, say), the tables it may cover are reported as "Floorplan can't tell whether … is protected", worth fixing rather than important, and a loop that does something else still leaves its tables reported. Reported by @doramirdor in #113.
- **Health says what it checked:** a clean Health panel could mean "checked and fine" or "nothing to check", for example when the scan found no endpoints in an app that has them. Below its summary, the panel now has **What was checked**, one line per check (endpoints, Supabase tables, Firebase rules files, Stripe webhooks, files read for secrets), saying what it looked at or that it found nothing. The line stands out when code looks like it runs a server (`createServer`, `Deno.serve`, a Supabase Edge Function) but no endpoints were found, or the app uses Supabase but no migrations were found. The build prints the same lines under HEALTH, and `--json` has them as `health.checked`. Suggested by @jstncrwn in #53.
- **Nuxt pages connect to the components and composables they use:** Nuxt auto-imports them, so pages had no import lines to follow and most Screens boards showed only the page itself. The scan now links a file to the components its template uses (`<WorkspaceTeam />`, `<workspace-team>`, `Lazy…`) and the composables and utils it calls, from the name lists Nuxt writes to `.nuxt/components.d.ts` and `.nuxt/imports.d.ts` (only those two files are read, and `.nuxt/` stays off the map), or from Nuxt's folder conventions when the app hasn't been built yet. Names a file imports or defines itself are left alone. Reported by @deniskern in #121.
- **Express and Hono routes on routers with any name:** the scan only read routes on routers called `app`, `router`, `routes` or `…Router`, so a Hono module's `export const frentes = new Hono()` or an Express `profileRoutes = Router()` lost all its endpoints, and Health could then call the app open. Routes on any router a file makes now count, a router mounted inside another one in the same file (`api.route('/frentes', frentes)`) gets both prefixes, and a login check for a path, like `app.use('/api/*', auth)`, protects the endpoints under it. Reported by @gen116sertoes in #98, fixed by @xunguangzlj-cloud in #103.
- **Express endpoints get the right address through factories and index files:** a mounted name that wasn't imported, like `const billingRoutes = createBillingRoutes()`, was taken for the mounting file itself, so everything that file served or mounted got the wrong prefix (`GET /api/billing/health`), sometimes several times over. Mounts now follow a function that returns a router, an index file that passes a router on (`export { default as authRoutes } from './auth.routes.js'`), `export *` and namespace imports, and a name handed to `app.use()` that isn't a router (middleware, a rate limiter) puts no prefix on anything. Reported by @xumbou in #71.
- **Open Express endpoints no longer hidden by look-alike middleware:** an app-wide `app.use(...)` counted as a login check whenever a guard-like word appeared anywhere in it, so Health stopped reporting every open endpoint behind it. A header name inside a string (`cors({ exposedHeaders: ['X-Refreshed-Token'] })`), an option's name, middleware that never turns anyone away (`cors`, `helmet`, `express-session`, `passport.session()` and the like) or only loads someone (`loadUser`, `optionalAuth`), a router (`app.use(authRoutes)`), a line that's commented out and a name that only says "guard" (`createShutdownGuard()`) no longer count. Real checks still do, including one listed after other middleware (`app.use(cors(), requireUser)`), `passport.authenticate('jwt')` and `authenticate`, which were missed before. When an app-wide check is all that protects some endpoints, the Health panel and the build's summary name it and where it is, so a clean result shows what it rests on. The "None of your endpoints check who is calling" title no longer shows `.` in place of a name for a project that is one repo at its root. Reported by @xumbou in #72, fixed by @ahmedjanwar in #85.

## 0.8.0 (2026-11-12)

- **An embedded map can hand "Ask about this" to the page around it:** an exported copy shown inside another page has no Ask bar, so its right-click menu had no Ask items. The page can now opt in by adding `ask=host` to the map's address. **Ask about this** then appears on cards, lines and the background, and sends that page a `floorplan:ask` message with the chosen items' ids and names, so its own Ask can take the question. Nothing changes for maps opened without it. See [Embedding the map](docs/using-the-map.md#handing-ask-about-this-to-the-page-around-the-map).

## 0.7.3 (2026-11-10)

- **A long description no longer covers the map in a short window:** when the map opened in a window that isn’t very tall (a laptop screen, or the map inside a frame), the heading’s description could run over the top row of boxes, because only part of the heading was kept clear when the map was fitted. The whole heading is now kept clear (up to just under half the window), and in a window under 760 pixels tall a long description folds to three lines with a More / Less toggle, as it already did on phones.

## 0.7.2 (2026-11-10)

- **A second build no longer fails when Floorplan is installed read-only:** the build puts two of its own files next to the map (`serve.mjs` and `page-safety.mjs`), and it copied them, permissions included. Where the plugin's files are read-only (some package managers, system-wide installs and locked-down machines install them that way), the copies were read-only too, so the next build stopped with a permission error (`EACCES` or `EPERM`) when it tried to replace them. They're now written fresh, so they can always be replaced, and a read-only copy left by an earlier version is replaced too.
- **`build.mjs --json` always prints its JSON object:** when the build stopped on something it didn't expect, it exited 1 with nothing on stdout, so a program reading the result couldn't tell what had happened. It now prints the usual object with `ok: false` and one error, like `build stopped unexpectedly (EACCES); see stderr`. The details still go to stderr, and never into the object, because they can quote your files.
- **A description file that isn't an object is reported, not a crash:** a file in `floorplan/descriptions/` holding `null` stopped the build, a refresh and `describe.mjs` with a stack trace. Now a file that holds `null`, a list or plain text, or whose `files` or `routes` holds a list, a number or text, is a build error that names it, like `descriptions/api.json must be an object like { "files": { … }, "routes": { … } }, not null`. `describe.mjs` treats such a file as empty and writes a fresh one to fill in, and a refresh leaves it for the build to name.
- **A tsconfig that extends itself no longer crashes the scan:** a `tsconfig.json` or `jsconfig.json` whose `extends` led back to itself, directly or through other configs, sent the scan round in circles until it ran out of stack. The loop now simply ends there.

## 0.7.1 (2026-11-10)

- **The map works when the browser blocks storage, copying or new windows:** embedded in a sandboxed iframe, in a private window, or with strict settings. Settings now hold while the page is open instead of resetting, the "Start here" tour no longer starts on every load (the button still starts it, and `#tour=0` in the address keeps it from starting on its own anywhere), copy buttons say "Copied" only when the text really was copied and otherwise select it for you, and links that would open a new window show their address instead of doing nothing. Links to a place on the map (`#v=…&s=…`) and embedding are now described in [Using the map](docs/using-the-map.md#links-to-a-place-on-the-map). Nothing changes where the browser allows these.
- **Truer descriptions:** maps now say what the code does today, not what its names suggest, so a half-built feature reads as "replies that a note was saved, without keeping it anywhere yet" instead of "saves notes". The writing guide has a new "Say what it does today" section, the description worksheets quote the code of each endpoint and of very short files (secrets masked, `.env` files never quoted, a few lines each), and they list which files import, request or name each file, so nobody has to guess who runs a script. The build also warns, never fails, when a part's name or summary on a map for everyone uses developer words ("API client", "UI kit", a framework's name), and when a part holds many files that sit in folders of their own.
- **Safer maps of code you didn't write, and safer copies to share.** A repository, or a description an AI or a person wrote about it, can no longer break, leak from or stall the map:
  - **One odd string can't blank the map:** text such as `<!--<script>` in an endpoint path, a file name or a description made the browser swallow the rest of the page, so the map drew nothing. The map's data now goes into the page with `<`, `>` and `&` written as escapes (the same data, nothing the browser can mistake for markup), through one helper used by the build, the map's server and its exports.
  - **Secrets written into descriptions are hidden:** if a description, label, summary, note or recent-work entry (or a comment the scan picked up) holds something that looks like a key or password, the map shows «hidden» and the build warns, naming the file and the field but never the value. Your files are left as they are. Ordinary words, file paths, commit hashes and IDs are left alone. Drivers can call the same check (`maskSecrets`) on text before writing it.
  - **Maps carry a Content-Security-Policy:** only the page's own scripts run (each allowed by its hash), and an exported copy can't contact anything at all, so even a script that somehow got in couldn't send the map anywhere. The map in `floorplan/` and the page the map's server serves may talk only to that local server. Everything works as before: Ask, flows, live reload, Export, the waitlist card and a blueprint's Change and Undo.
  - **A bad pattern is an error you can fix, not a crash:** a glob in `architecture.json` that isn't valid (an unclosed `[` or `{`, a backwards range), or is absurdly long or wild, used to stop the build with a stack trace. Now it's a build error that says where it is, like `nodes[3] ("web").paths[0] "[evil" is not a valid pattern`.
  - **No more stalled scans:** a large `tsconfig.json` full of `/*` kept the scan busy for minutes. Comments are now stripped in one pass, config files over 1 MB are skipped with a note, and the patterns that read code (imports, endpoints, requests, comments, Health's checks, screens) no longer slow down sharply on large or unusual files.
  - **Names can't pretend to be something else:** invisible characters and ones that reverse the text around them (which can make one file name read as another) are shown on the map as a visible marker like `[U+202E]`. The files keep their real names underneath.
- **Fewer wrong plain-language warnings:** "hook" is flagged only where it means a React-style hook ("custom hooks", "the useCart hook"), not a template's set-up hooks or git hooks; "component" and "primitives" only on parts that are screens (or when said outright, "UI components"); and "shell" only as "app shell", not a shell script.
- **Rewording never fails the map:** in the workflow file, the step that rewords labels and summaries the build flags is now optional and may change only their wording. If the model gives no valid answer, changes anything else, or the reworded file doesn't build, the earlier architecture.json is put back and the map carries on. The workflow format gains `optional`, `restore`, `onFail`, `minAttempts` and a job's `onlyChange` ([Running without an agent session](docs/unattended.md#the-workflow-file)).

## 0.7.0 (2026-11-09)

- **Run Floorplan without an agent session:** in CI, in a script, or from your own tooling, with any model that can read files and return JSON. See [Running without an agent session](docs/unattended.md).
  - **Unattended mode** (`FLOORPLAN_UNATTENDED=1`, or `--unattended`): nothing is written outside `floorplan/` (no `CLAUDE.local.md`, no `.git/info/exclude`, no moving an old section out of `CLAUDE.md`), the map names no agent, `open.mjs` starts nothing, and a refresh whose build fails, or that finds no map, exits with an error.
  - **Results as JSON:** `--json` on `scan.mjs`, `build.mjs`, `describe.mjs`, `refresh.mjs`, `recent.mjs` and `status.mjs` prints one JSON object instead of the report. A refresh's NEXT list comes with stable codes (`fix_build`, `assign_new_files`, `describe`, `review_structure`, `recent_work`) a program can act on.
  - **The workflow as data:** `skills/floorplan/workflow.json` describes the steps SKILL.md takes, which script to run, which jobs need a model, what each is given, the schema of its answer and when it's done, so a small program can follow it. A new test follows it through a first map and a refresh, so it keeps working.
  - **Maps that name no agent:** `FLOORPLAN_AGENT=none` (which unattended mode implies) makes the map's buttons say "Fix with AI" rather than naming Claude or Codex.
- **A repo git can't read no longer disappears quietly:** if git isn't installed, or refuses a checkout because a different user owns it ("dubious ownership", common in containers), the scan now names the repo and the fix instead of leaving it off the map without a word. In unattended mode, that and finding no files at all are errors.
- Nothing changes for people using Floorplan in Claude Code or Codex.

## 0.6.3 (2026-11-02)

- **Endpoints in route tables** (#54, from @Yahhi): servers without a framework often keep their endpoints in a lookup a dispatcher reads, keyed by method and path, like `{ "GET /api/orders": listOrders }` in JavaScript or a Python dict of handlers behind a cloud function. Floorplan found no endpoints in these apps, so the website's requests weren't linked to the server. Now each key is an endpoint, named after its handler (a function, an inline function that calls one, or a wrapped one like `requireAuth(createOrder)`). Tables of other things keyed the same way, like access levels or notes, are left alone. Health doesn't judge sign-in on these endpoints, because the dispatcher or the handler checks it where Floorplan can't see.
- **Fastify endpoints get their full address** (#30, from @secatech): a plugin mounted with `app.register(plugin, { prefix: '/api/tickets' })` now puts its endpoints under that prefix, including plugins registered inside other plugins and ones loaded with `import()` or `require()`. Before, every plugin's endpoints sat at the root (`GET /`, `GET /:id`), so the website's requests were often matched to the wrong part of the server.
- **Django endpoints get their full address:** an app's `urls.py` included by the project (`path("api/orders/", include("orders.urls"))`) now puts its endpoints under that prefix, as `/api/orders/<int:pk>` rather than `/<int:pk>`, so the website's requests link to them. The include line itself is no longer listed as an endpoint, and the project's `urls.py` links to the app's. Fixed by @rudycelekli (#64).
- **Code after a `/*` inside a string is read again:** a string such as `'/api/*'` (as in Hono's `app.use('/api/*', cors())`) was taken for the start of a comment, so every endpoint, import and web request from there to the next comment's end was missing from the map. Fixed by @rudycelekli (#61).
- **Skill installation:** quote the YAML description so `npx skills add` can read it. Fixed by @Bl0ck154 (#25), and @Mason-Little sent the same fix.
- **Blueprints in Codex:** the build report now says a blueprint is "planned, not built yet" in Codex too. Fixed by @owlahikit.

## 0.6.2 (2026-11-02)

- **Far fewer false alarms in Health** (thanks to @samuelpullen15-droid, who reported 13 of them from one site with the new **Not a problem** button):
  - **Feeds and files meant for everyone:** reading `rss.xml`, `atom.xml`, `llms.txt`, `ads.txt` and similar no longer counts as an open endpoint.
  - **Addresses you publish yourself:** an endpoint listed in your `llms.txt`, or allowed in your `robots.txt`, is public on purpose. A catch-all route counts when something under it is listed, and a blocked or merely nearby address doesn't.
  - **Responses marked for everyone:** a `Cache-Control: public` response is public on purpose, including when a helper it imports sets the header. So is a Next.js route with `force-static` or `revalidate`.
  - **Nothing private to give:** a Next.js `GET` that reads no database, session, cookie or server secret, directly or through what it imports, is no longer reported. A rate limiter's Redis doesn't count, an import Floorplan can't follow does, and so does reading files on a route whose address the caller chooses.
  - **Payload CMS:** the API routes Payload generates apply its own access rules, so they no longer read as "anyone could change data".
  - **A "POST only" reply:** a handler that only answers 405 isn't an open endpoint or a way to send fake events.
  - **Webhooks locked with a shared secret:** comparing against a secret from the environment, `timingSafeEqual`, and helpers like `isAuthorized()` or `verifyWebhookSecret()` now count as checks on Next.js routes.
  - **A browser tracker's site token:** a token handed to a tracker's `<script>` tag is one every visitor already has. Names like `ACCESS_TOKEN` or `AUTH_TOKEN`, and real key formats, are still reported.
  - **Files a tool opens by name:** a file whose comment says a tool reads it, or that it's generated, no longer looks unused.
  - Endpoints that change data are still always checked, and "Not a problem" is still there for anything Health can't work out.
- **FastAPI checks Health missed** (#7), fixed by @Bl0ck154: dependencies named like `metrics_guard`, a token in a `Header` parameter when the handler rejects a bad one, a Twilio-style signature check inside a helper, and `/readyz` and `/livez` as public health checks.

## 0.6.1 (2026-11-01)

- **Fewer false alarms in Health** (thanks to the user who reported these):
  - **A password hash isn't the password:** bcrypt, argon2 and similar hashes are no longer reported as passwords, and neither is anything under a name like `ADMIN_PASSWORD_HASH`, including browser variables such as `VITE_ADMIN_PASSWORD_HASH`. The secret that makes a hash (`HASH_SECRET`) is still flagged, and so is a real key format under any name.

Exported copies keep the issue set apart but leave your reason out.

## 0.6.0 (2026-10-31)

- **Health catches the classic mistakes in AI-built apps.** Five new checks, each in plain words with a fix to paste:
  - **Secret keys sent to the browser:** an OpenAI, Stripe or Supabase service-role key (and others) in a `NEXT_PUBLIC_`, `VITE_`, `REACT_APP_` or similar variable, which every visitor can read. Keys that are public by design, like Supabase's anon key or Stripe's publishable key, are left alone.
  - **Supabase tables anyone can read and change:** tables whose row-level security is never switched on (or is switched off), worked out by replaying the migrations in order, so a table locked later or dropped doesn't count. Policies that let anyone add, change or delete rows are flagged too, as worth a look.
  - **Firebase rules that let anyone in:** Firestore, Storage and Realtime Database rules open to anyone, including "test mode" rules, with the date they stop working (or stopped).
  - **Stripe webhooks anyone could fake:** code that acts on events like `checkout.session.completed` without checking Stripe's signature, so anyone could send a fake "payment succeeded".
  - **Servers that let any website call them (CORS):** a small note on its own, and worth fixing when login cookies are allowed along with it.
- **No more false alarm on Supabase's `config.toml`:** values like `"env(S3_SECRET_KEY)"` read a setting from the environment, so they're no longer reported as a key written into the code.

## 0.1.0 (2026-10-27)
